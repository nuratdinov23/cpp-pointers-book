3. Промпт C (написание темы) — для каждой темы Т1–Т30. В чат вставляется «Общий блок», затем Промпт C. Результат Промпта B по этой теме и записи глоссария и зависимостей из Промпта A вставляются в раздел «Входные материалы».
При расхождении глоссарий из Промпта A главнее остальных материалов.
Общий блок (вставлять в начало каждого чата)
КОНТЕКСТ КНИГИ
Книга-руководство по C++ для начинающих программистов. Общая тема: УКАЗАТЕЛИ в C++ (все виды указателей, умные указатели, приведения, диагностика).
Язык: русский. Термины пиши по-русски, в скобках — официальный английский.
Стандарт по умолчанию: C++17. Особенности C++11, C++14, C++20 помечай явно, если они важны для темы.

СТИЛЬ
Только сухая, краткая, академическая теория. Без воды, приветствий, аналогий и лирических отступлений. Всё объясняй на конкретном коде.

МАРКЕРЫ ВАЖНОСТИ (строго только эти четыре)
[ВАЖНО] — главное правило или факт темы.
[ЗАПОМНИТЬ] — то, что нужно помнить наизусть.
[ПОНЯТЬ] — то, что нельзя заучить, нужно понять механизм.
[ОПАСНО] — типичная ошибка или Undefined Behavior (UB).

ЧЕСТНОСТЬ
Если не уверен в факте или в том, что говорит стандарт, пиши: «[НЕ УВЕРЕН]: ...». Номера разделов стандарта указывай только если уверен на 100%. Для UB и спорных мест указывай, что именно утверждает стандарт.

ПРАВИЛО ИЗОЛЯЦИИ ТЕРМИНОВ
При изложении теории и определений СТРОГО ЗАПРЕЩЕНО использовать технические понятия, которые не были объяснены ранее. Если нужно новое сложное понятие — сначала дай определение прямо в тексте. «Ранее» означает: в этой теме или в темах с меньшим номером по карте тем (ниже). Понятие из ещё не пройденной темы разрешено только по правилу ссылок.

ПРАВИЛО ССЫЛОК МЕЖДУ ТЕМАМИ
- Если понимание места зависит от другой пройденной темы: [СМ. Т<номер>: что именно там нужно знать] + минимум 1–2 строки пояснения, чтобы можно было читать дальше.
- Если нужная тема ещё не пройдена: [ПОДРОБНО В Т<номер>, сейчас достаточно знать: ...].
- В конце темы выводи строку: «Эта тема нужна для: Т..., Т...».

ТАКСОНОМИЯ (не нарушать, не смешивать оси)
Настоящие ТИПОВЫЕ виды: указатель на объект T*; void*; указатель на массив T(*)[N]; указатель на функцию; указатель на поле класса; указатель на метод класса; тип std::nullptr_t.
НЕ являются отдельными видами:
- «указатель на элемент массива», «на C-строку», «на объект класса», «на указатель» — это тот же T* в разных ролях или с другим T;
- nullptr — значение; this — выражение (его нельзя объявить или перенацелить);
- нулевой, неинициализированный (wild), висячий (dangling), утечка (memory leak) — СОСТОЯНИЯ, а не виды;
- умные указатели — классы стандартной библиотеки, а не указатели языка; итераторы и ссылки — не указатели.
Оси классификации: по типу, по константности (const/volatile/constexpr), по владению (сырой/умный), по состоянию.
Не все операции применимы ко всем видам (арифметика не работает с void*, указателями на функции и на члены). Всегда явно пиши, что применимо, а что нет.

Промпт A. Глобальный каркас проекта
ЗАДАЧА: АРХИТЕКТУРНЫЙ АНАЛИЗ ДО НАПИСАНИЯ ГЛАВ
Мы проектируем монолитную книгу об указателях в C++17. Чтобы в ней не было логических нестыковок, до написания глав нужно сформировать Глобальный Каркас Проекта. Весь анализ выполни за один ответ. Лекций не пиши.

ИСХОДНЫЕ ДАННЫЕ И ГРАНИЦЫ
1. КАРТА ТЕМ (Т1–Т30) из общего блока — рабочая версия. Проверь её: порядок, зависимости, полноту, соответствие таксономии. Если нужно что-то добавить, переставить, разделить или убрать — не меняй молча. Сначала выведи список «Было / Стало / Почему», дальше работай по исправленной карте.
2. Границы: только то, что относится к указателям. Всё остальное из C++ (переменные, функции, классы, шаблоны, перечисления, ссылки и т. д.) — «внешние предпосылки». Для каждой укажи: что именно нужно знать читателю и в какой теме достаточно дать минимум одной строкой по правилу ссылок.
3. Каждая подглава = один чат = одна узкая тема.

ВЫВЕДИ РЕЗУЛЬТАТ СТРОГО В 4 БЛОКАХ.

БЛОК 1: СЕГМЕНТИРОВАННОЕ ОГЛАВЛЕНИЕ
Модули (этапы) → Главы → атомарные подглавы. Для каждой подглавы: номер Т, название, уровень (базовый / углублённый / по желанию), одна строка о том, что она закрывает. Не объединяй в одну подглаву две независимые темы.

БЛОК 2: СКВОЗНАЯ КАРТА ТЕРМИНОВ (ГЛОССАРИЙ КНИГИ)
Все фундаментальные термины книги в порядке первого появления. Для каждого: термин (English) — сухое определение — номер Т, где термин вводится впервые.
Условие: определение термина не должно использовать термины с большим номером Т первого появления, чем у самого термина. Этот список станет введением в терминологию, поэтому термины не переопределяются в темах заново, только вспоминаются по ссылке.
Не смешивай виды, состояния и роли (см. таксономию): у каждого термина укажи, чем он является — вид, состояние, роль, операция, класс библиотеки или механизм языка.

БЛОК 3: МАТРИЦА ЗАВИСИМОСТЕЙ
Для каждой темы Т1–Т30 (и главы целиком):
- предварительные требования: номера тем и конкретные термины из глоссария, которые читатель обязан знать железно;
- внешние предпосылки (не из книги);
- допустимые опережающие ссылки: что из более поздней темы можно упомянуть и какой минимум сказать (формат [ПОДРОБНО В Т.., сейчас достаточно знать: ...]);
- запрещённые термины: что из непройденного упоминать нельзя вообще.

БЛОК 4: ГЛОБАЛЬНЫЙ РЕЕСТР ОШИБОК И UB
Упорядоченный список ошибок от простых к сложным. Для каждой: название; категория (Ошибка компиляции / Ошибка линковки / Ошибка выполнения / Утечка памяти / Undefined Behavior); номер Т, где она разбирается подробно (ровно одна тема, без дубликатов; в других темах только [СМ. Т..]); одна строка с признаком в коде.
Отправная точка, которую нужно проверить и дополнить: int* a, b; несовпадение типов (double d; int* p = &d;); число вместо адреса (int* p = 5;); char* s = "abc"; const-указатель без инициализации; разыменование неинициализированного и нулевого указателя; адрес временного объекта; возврат адреса локальной переменной (висячий указатель); несовпадение new[] и delete; двойное удаление; сужающее преобразование в {}.

ШАГ 3 (по команде): Рабочий пример на C++17
Один чистый минимальный компилируемый пример по теме Т[НОМЕР], без привлечения непройденного. Правила кода и обязательные инженерные объяснения («почему»). Каждое объяснение даётся ОДИН раз в заметном месте под маркером важности; если оно уже давалось в предыдущей теме, дай одну строку со ссылкой [СМ. Т..].
1. constexpr вместо #define для констант. Объясни: типобезопасность, область видимости, поддержка отладчиком.
2. Сырые Си-массивы int arr[N] запрещены, использовать std::array (для получения указателя — arr.data()). Объясни: нет контроля границ, неявное приведение к указателю, потеря размера при передаче в функцию.
   ИСКЛЮЧЕНИЕ: в темах Т10, Т11, Т14, Т27 сырой массив разрешён, если он предмет темы. Помечай такую строку комментарием «// сырой массив: предмет темы».
3. nullptr вместо 0 и NULL. Объясни: nullptr имеет отдельный тип std::nullptr_t, а не «просто ноль», и защищает при перегрузке функций. 0 и NULL допустимы только в блоке ошибки (Шаг 4).
4. Const Correctness для указателей:
   - не меняем данные через указатель → const T*;
   - не перенаправляем указатель → T* const;
   - ни то ни другое → const T* const;
   - любая неизменяемая переменная → const.
   Объясни, как это помогает компилятору оптимизировать, а программисту избегать случайных мутаций. Подробности — Т6.
5. std::string_view вместо const std::string& для чтения строк. Объясни: быстрее, не делает аллокаций в куче.
6. Сырые new/delete запрещены, использовать std::unique_ptr / std::shared_ptr. Объясни: RAII исключает утечки по вине забытого delete.
   ИСКЛЮЧЕНИЕ: new/delete разрешены в темах Т12, Т17, Т20 (предмет темы или демонстрация того, что заменяет RAII). Каждое использование помечай комментарием «// сырой new/delete: предмет темы» и сразу показывай парный delete/delete[].
   Начиная с Т21 new/delete в основном примере запрещены: создавай через std::make_unique и std::make_shared (в C++17 std::make_unique<T[]> разрешён, new T[] нет).
7. Приведения только через static_cast<T>(x). Объясни: Си-кастинг (int)x может незаметно выполнить reinterpret_cast или const_cast и скрыть ошибку.
   ИСКЛЮЧЕНИЕ: в Т24 и Т25 разрешены dynamic_cast, const_cast, reinterpret_cast, но только как предмет темы, с пометкой и пояснением опасности. Си-каст разрешён только в блоке ошибки.
8. enum class вместо enum, если перечисление вообще нужно в примере. Объясни: загрязнение глобального пространства имён, запрет неявных сравнений разных типов.
9. Тяжёлые объекты (std::string, std::vector и т. п.) передавать по const T&, если они не изменяются. Объясни разницу между дешёвой копией ссылки и дорогой копией данных.
   ПРИМЕЧАНИЕ: сам указатель (8 байт на 64-битной платформе) копировать по значению дёшево; не путай с копированием объекта, на который он указывает.
Стандарты оформления:
- Строго без `using namespace std;`, все сущности пиши с `std::`.
- Только списочная инициализация `{}`, включая указатели: `int* p{&x};`, `int* p{};` (получается nullptr). Объясни один раз: защита от сужающих преобразований (`int* p{5};` — ошибка компиляции), решение Most Vexing Parse.
- Один указатель — одна строка (ловушка `int* a, b;`).
- Любой указатель, который может быть nullptr, проверяй перед разыменованием.
Ниже кода — построчный разбор в формате «Строка Х: [Конкретное действие]». Для каждой строки, работающей с памятью, укажи: изменяется АДРЕС (значение самого указателя), ЗНАЧЕНИЕ (данные по адресу) или ничего не меняется, и где лежит изменяемая ячейка (стек/куча/статическая). Жди «Дальше».

ШАГ 4 (по команде): Типичная ошибка новичка
Структура блока строго:
1. Блок кода с ошибкой и маркером [ОПАСНО]. Здесь допускаются конструкции, запрещённые правилами Шага 3, если они и есть суть ошибки (NULL, Си-каст, сырой new без delete и т. п.).
2. Категория последствий (одна из): Ошибка компиляции / Ошибка линковки / Ошибка выполнения / Утечка памяти / Undefined Behavior.
3. Что скажет компилятор: если ошибка компиляции — примерный лог GCC/Clang на английском и на какое ключевое слово смотреть. Если ошибка выполнения или UB — что может проявиться (падение, мусор, «работает случайно») и какой инструмент поймает (предупреждение -Wall, санитайзер). Если инструмент ещё не пройден (Т28) — по правилу ссылок.
4. Причина: одна-две строки, что происходит в памяти (адрес, объект, время жизни).
5. Исправление: сразу ниже правильный вариант того же кода (по всем правилам Шага 3).
Ошибку бери из реестра (Промпт A, Блок 4), если он приложен; не повторяй ошибки, закреплённые за другими темами. Жди «Дальше».
